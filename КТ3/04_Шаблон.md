## Кратко: что нужно исправить в `mediapolka.py`

1. **R2:** условие `quantity >= 3` должно быть `quantity > 3` (сейчас 3 отклоняется).
2. **R3:** проверять `available < quantity`, а не `available < 1` (сейчас можно выдать больше, чем есть).
3. **R6:** в `return_loan` сначала находить запись; если `status == "returned"` — возвращать «Уже возвращено» без изменения остатка; иначе возвращать оборудование.

Дополняйте строки по ходу исследования. Планируемые проверки не помечайте как выполненные до реального запуска.

## 2. Причины и исправления

### Найденная причина 1

- Правило, данные и шаги: R2. `state = new_state()`; `issue(state, "mic", "3")`. Количество «3» допустимо по R2 (1, 2, 3 включительно).
- Ожидалось / получилось до исправления: ожидалось `ok=True`, «Выдано», остаток `mic = 0`; получилось `ok=False` (тест `test_allowed_quantities` с `quantity_text='3'` падает на `assertTrue(result["ok"])`).
- Обнаруживающий тест и файл вывода до исправления: `test_allowed_quantities` (`quantity_text='3'`), вывод `FAIL ... AssertionError: False is not true`.
- Причина в коде и изменение: в `issue` условие `if quantity < 1 or quantity >= 3:` отклоняет 3. Заменено на `if quantity < 1 or quantity > 3:` — теперь 3 разрешено, а 4 и больше отклоняются.
- Повторная и соседняя проверки: `test_allowed_quantities` (все три количества), `test_invalid_quantities` (0, 4, 10 и др.), `test_r2_before_r3`, `test_whitespace_trimmed`.

### Найденная причина 2

- Правило, данные и шаги: R3. `state = new_state()`; `issue(state, "mic", "3")` (остаток 0), затем `issue(state, "mic", "1")`; отдельно проверить выдачу больше остатка: остаток 1, запрос 2. Также `issue(state, "light", "1")` при остатке 0.
- Ожидалось / получилось до исправления: ожидалось `ok=False`, «Недостаточно оборудования», состояние без изменений; получилось `ok=True` (тест `test_more_than_available` падает на `assertTrue(result["ok"])` для первой выдачи 3 — из-за причины 1; после исправления R2 выявляется вторая причина: проверка `available < 1` пропускает выдачу больше остатка).
- Обнаруживающий тест и файл вывода до исправления: `test_more_than_available`, вывод `FAIL ... AssertionError: False is not true` (строка 79).
- Причина в коде и изменение: в `issue` проверка `if available < 1:` не сравнивает запрошенное количество с остатком. Заменено на `if available < quantity:` — отказ, если запрошено больше, чем есть; сообщение «Недостаточно оборудования», состояние не меняется.
- Повторная и соседняя проверки: `test_more_than_available`, `test_zero_stock`, `test_zero_tripod`, `test_allowed_quantities` (выдача ровно остатка), `test_r2_before_r3` (R2 раньше R3).

### Найденная причина 3

- Правило, данные и шаги: R6. `state = new_state()`; `loan_id = issue(state, "mic", "2")["loan_id"]`; `return_loan(state, loan_id)`; повторно `return_loan(state, loan_id)`. Также `return_loan(state, 99)` для неизвестного ID.
- Ожидалось / получилось до исправления: ожидалось при повторе `ok=False`, «Уже возвращено», остаток и записи без изменений; получилось `ok=True`, остаток снова увеличился (тест `test_double_return_rejected_unchanged` падает на `assertFalse(result["ok"])`).
- Обнаруживающий тест и файл вывода до исправления: `test_double_return_rejected_unchanged`, вывод `FAIL ... AssertionError: True is not false` (строка 169).
- Причина в коде и изменение: `return_loan` находит запись по ID и сразу возвращает оборудование, не проверяя `status`. Изменено: после поиска записи проверять `if loan["status"] == "returned": return {"ok": False, "message": "Уже возвращено"}` без изменения состояния; иначе — вернуть оборудование, статус `returned`, ответ «Возвращено». Неизвестный ID по-прежнему даёт «Выдача не найдена».
- Повторная и соседняя проверки: `test_double_return_rejected_unchanged`, `test_unknown_id_rejected_unchanged`, `test_return_on_empty_state`, `test_return_restores_stock`, `test_return_does_not_change_next_id`, `test_issue_return_issue_again`.
